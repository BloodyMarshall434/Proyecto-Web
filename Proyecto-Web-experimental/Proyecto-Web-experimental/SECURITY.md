Security Policy
Supported Versions

We actively maintain and provide security updates for the following versions of this project.

Version	Supported
Latest release	:white_check_mark:
Older releases	:x:

Security fixes are prioritized for the latest stable release.

Reporting a Vulnerability

We take the security of this project seriously. If you discover a security vulnerability, please report it responsibly.

Please DO NOT report security vulnerabilities through public GitHub Issues or Discussions.

Instead, use one of the following methods:

GitHub Security Advisories: Use the Report a vulnerability feature in this repository.
Private contact: Contact the repository maintainers privately through GitHub.

When reporting a vulnerability, please include:

A description of the vulnerability.
Steps to reproduce the issue.
The potential impact and severity.
Affected versions or components.
Any suggested fixes or mitigations, if available.
Response Timeline

We aim to follow these response guidelines:

Action	Expected timeframe
Initial acknowledgment	Within 72 hours
Vulnerability assessment	Within 7 days
Status update	Within 14 days
Security fix	Depending on severity and complexity

These timelines are goals and may vary depending on the complexity of the issue.

Responsible Disclosure

We request that security researchers:

Give maintainers reasonable time to investigate and fix reported vulnerabilities.
Avoid publicly disclosing vulnerabilities before a security fix is available.
Do not exploit vulnerabilities beyond what is necessary to demonstrate the issue.
Do not access, modify, or delete other users' data.
Do not perform denial-of-service attacks or other disruptive testing.
Act in good faith and respect the privacy of project users.
Scope

The following are generally considered valid security issues:

Authentication and authorization vulnerabilities.
Remote code execution (RCE).
SQL injection and other injection vulnerabilities.
Cross-site scripting (XSS).
Sensitive information or credential exposure.
Privilege escalation.
Insecure handling of user data.
Security misconfigurations that have a demonstrable impact.

The following are generally out of scope:

Social engineering attacks.
Physical attacks.
Denial-of-service attacks.
Vulnerabilities in outdated third-party software that are not caused by this project.
Issues requiring unlikely or unrealistic user interaction.
Reports without a demonstrable security impact.
Security Best Practices

Users and contributors should:

Keep dependencies up to date.
Never commit API keys, passwords, tokens, or other secrets.
Use environment variables for sensitive configuration.
Follow the principle of least privilege.
Review third-party dependencies before introducing them.
Enable multi-factor authentication (MFA) on GitHub accounts.
Use secure coding practices and validate untrusted input.
Disclosure Policy

Once a vulnerability has been verified and addressed, maintainers may publish a security advisory describing:

The nature of the vulnerability.
Its potential impact.
Affected versions.
The patched versions.
Recommended mitigation steps.

We appreciate responsible security researchers who help keep this project and its users safe.

Contact

For security-related questions or concerns, please contact the repository maintainers through GitHub's private vulnerability reporting feature.

Thank you for helping improve the security of this project.
